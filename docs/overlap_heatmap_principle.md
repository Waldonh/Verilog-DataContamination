# 10 方法污染检测重叠热力图：构造原理

> 本文档详细说明"10 个污染检测方法之间共同污染样本数热力图"的构造原理，从数据源头到最终可视化逐步展开。

**分析范围**：该重叠分析在 **5 个被测模型（ChipGPT / RTLCoder / OriGen / VeriCoder / VeriGen）× 6 个 benchmark（VerilogEval_v1/v2、RTLLM_v1/v2、RealBench_module/system）** 上进行。overlap 矩阵**不是针对单个模型**，而是把这 5×6 个 model-benchmark 对的全部样本合并成一个全局样本池后，统计方法两两之间的共同污染样本数（即"综合所有模型与 benchmark"的全局结果）。

---

## 1. 第一步：每个方法独立判污染

对 benchmark 的**每一个样本**，10 个方法各自用**自己的固定阈值**给出一个 0/1 判定（1 = 污染，0 = 干净）。

| 方法 | 阈值 + 方向 |
|---|---|
| Zlib | `score ≥ -0.003` |
| Min-K% | `score ≥ -3.0` |
| Min-K%++ | `score ≥ -3.0` |
| DC-PDD | `score ≤ -3.0` |
| PPL | `score ≥ -2.2` |
| PETAL | `score < 0.8` |
| Neighbor | `score ≥ 0.8` |
| Reference | `score ≥ 0.13` |
| Token Overlap | `score ≥ 0.55` |
| CDD | `score > 0.01` |

于是每个样本会得到 10 个判定结果（10 个方法各判一次）。

## 2. 第二步：收集每个方法的"污染样本集合"

把所有 (model, benchmark) 对的样本**合并成一个全局样本池**，每个样本赋予一个唯一编号（例如 `ChipGPT|VerilogEval_v1|3`）。

然后对每个方法 M，收集**它判为污染的所有样本编号**，得到一个集合：

```
contaminated_sets["Zlib"]   = {样本1, 样本5, 样本9, ...}
contaminated_sets["Min-K%"] = {样本2, 样本5, 样本7, ...}
...
```

## 3. 第三步：计算 overlap 矩阵（核心）

矩阵的每个元素 `overlap[i][j]` = **方法 i 和方法 j 的污染样本集合的交集大小**：

```
overlap[i][j] = | contaminated_sets[i] ∩ contaminated_sets[j] |
```

即"方法 i 和方法 j **共同**判为污染的样本数"。

- **对角线** `overlap[i][i]` = 方法 i 判为污染的样本总数（集合与自己求交集 = 集合自身）；
- **非对角线** `overlap[i][j]` = 两个方法"意见一致判污染"的样本数。

矩阵是对称的（`overlap[i][j] = overlap[j][i]`），因此画图时只画**下三角 + 对角线**即可。

## 4. 第四步：画成热力图

- 从 `overlap_matrix.csv` 读入矩阵；
- 用 `np.triu(..., k=1)` 屏蔽上三角（对称矩阵避免重复）；
- 用 `Blues` 色图，颜色深浅表示共同污染样本数的多少（越深越多）；
- 每个格子标注数值。

## 5. 热力图说明了什么

关键看**非对角线 vs 对角线**的对比：

- 之前那版矩阵的**对角线**（各方法判污染的样本总数）为：

  PPL 2255、Min-K%++ 1751、Reference 1659、DC-PDD 1564、CDD 966、Zlib 958、Neighbor 909、Min-K% 700、Token Overlap 501、PETAL 363。

- 而**非对角线**（方法间共同判污染的样本数）普遍远小于对角线——即每个方法判出的"污染样本"彼此重叠很少，**各判各的**。

这直接说明一个结论：**10 个方法的检测结果高度不一致（两两重叠率低），单一方法不可靠**，因此需要将多个方法**集成融合**（这正是 CatBoost-5f 集成探测器的动机来源）。

---

## 一句话总结

**热力图 = 每两个方法"同时判污染"的样本数矩阵的可视化**，通过"非对角线远小于对角线"来展示方法间的分歧，进而引出集成融合的必要性。
